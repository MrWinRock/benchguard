# BenchGuard v0.1.1 Usability Design

Date: 2026-07-29
Status: Approved conversational design, pending written-spec review

## 1. Objective

BenchGuard v0.1.1 fixes target-command parsing through npm's generated
PowerShell launcher and makes human-facing output easier to read. The patch
keeps the v0.1 JSON schema and comparison behavior stable.

## 2. Command syntax

`record` and `check` accept target commands with or without the explicit `--`
delimiter:

```console
benchguard record npm-build --max-time +10% npm run build
benchguard record npm-build --max-time +10% -- npm run build
benchguard check npm-build
benchguard check npm-build npm run build
benchguard check npm-build -- npm run build
```

The delimiter-free form is the primary documented syntax. The delimited form
remains supported for backward compatibility and for scripts that prefer an
explicit boundary.

All BenchGuard options must appear before the target executable. Once the
target executable begins, every remaining token belongs to the target,
including tokens beginning with `-`. Argument boundaries remain unchanged.

This native parsing change fixes npm's generated PowerShell `.ps1` shim and
`npx`, both of which may consume a standalone `--` before the Rust executable
receives it. It also gives Cargo and standalone-binary installations the same
interface.

## 3. Human-readable units

Human reports automatically scale metric values while retaining enough
precision to understand meaningful differences:

- Wall and CPU time use `ns`, `µs`, `ms`, or `s`.
- Memory uses `bytes`, `KiB`, `MiB`, or `GiB`.
- Values below the next unit boundary remain in the smaller unit.
- Scaled values use at most two fractional digits and trim unnecessary trailing
  zeroes.
- Signed deltas retain their sign.

Representative output:

```text
npm-build: PASS
  wall time:
    baseline: 428.6 ms
    current median: 441.2 ms
    delta: +12.6 ms (+2.94%)
  CPU time:
    baseline: 311.2 ms
  peak memory:
    baseline: 84.7 MiB
```

Calculations and comparisons continue to use integer nanoseconds and bytes.
JSON field names, integer values, status values, and error envelopes remain
unchanged.

## 4. Color behavior

Human output supports a global option:

```console
--color auto|always|never
```

The default is `auto`.

As a global option, `--color` is accepted before or after the subcommand as
long as it appears before a delimiter-free target executable.

- `auto` emits color only when standard output is an interactive terminal.
- `always` emits color for human reports even when output is redirected.
- `never` emits no ANSI styling.
- A present `NO_COLOR` environment variable disables color when the effective
  mode is `auto`.
- JSON output never contains ANSI escapes, including with `--color always`.

The palette communicates meaning without making color the only signal:

- Green: `PASS` and `RECORDED`.
- Red: `REGRESSED` and human error labels.
- Yellow: warnings and `UNBUDGETED`.
- Cyan: benchmark names and section headings.
- Dim/default: secondary statistics and units.

Every colored value retains its existing text label so reports remain
understandable without color.

## 5. Help and examples

Top-level and subcommand help include a notation legend:

```text
Notation:
  <VALUE>   required
  [VALUE]   optional
  ...       repeatable
```

Help explains `<NAME>`, `<TARGET>...`, `[TARGET]...`, and `[OPTIONS]` in plain
language. Examples use realistic npm and Bun build commands:

```console
benchguard record npm-build --max-time +10% npm run build
benchguard check npm-build
benchguard record bun-build --max-time +10% bun run build
benchguard list --format json
```

`benchguard help`, `benchguard help record`, `benchguard help check`, and
`<command> --help` expose the relevant examples.

## 6. Implementation boundaries

- `cli` owns optional-delimiter parsing, the color option, and help text.
- `report` owns adaptive human units and ANSI styling.
- JSON serialization remains separate from human rendering and is not modified.
- The npm launcher continues forwarding the argument array unchanged; the
  native CLI becomes tolerant of shims that omit `--`.
- No new runtime service, configuration file field, baseline schema version, or
  platform is introduced.

## 7. Testing

### Parser tests

- `record` accepts a target with and without `--`.
- `check` accepts an optional override with and without `--`.
- Target arguments beginning with `-` remain target arguments.
- BenchGuard options before the target retain their existing behavior.
- The explicit delimiter remains backward compatible.

### npm Windows tests

A packed-and-installed npm CLI is invoked through the generated PowerShell
`.ps1` shim with a real `record` command. The test proves that the target
executable and its leading-hyphen arguments reach the native binary.

### Formatting tests

- Boundary values select the correct time and memory unit.
- Fractional digits and signed deltas are stable.
- `auto`, `always`, `never`, and `NO_COLOR` follow the documented behavior.
- Status text remains present alongside color.
- JSON output is byte-for-byte free of ANSI escape sequences and keeps raw base
  units.

### Help tests

Existing help-contract tests are updated to require the notation legend,
delimiter-free syntax, npm/Bun examples, and `--color` documentation.

### Full verification

Formatting, clippy, unit tests, integration tests, npm launcher tests,
documentation contracts, release contracts, and Windows/Linux GitHub Actions
must pass before release.

## 8. Release scope

- Bump Cargo and all npm package versions from `0.1.0` to `0.1.1`.
- Update `Cargo.lock`, `CHANGELOG.md`, README examples, JSON documentation only
  where human-output examples change, and release acceptance tests.
- Publish Windows and Linux archives with checksums.
- Publish all three npm packages through trusted publishing.
- Publish `benchguard 0.1.1` to crates.io.
- Verify clean npm and Cargo installations report `benchguard 0.1.1`.

The release does not add macOS, ARM, new metrics, baseline migrations, or
comparison-policy changes.
