# BenchGuard v0.1.1 Usability Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Release BenchGuard v0.1.1 with delimiter-free target commands, adaptive human units, controlled ANSI color, and example-driven help while preserving v1 JSON.

**Architecture:** Clap accepts the target as a trailing positional with or without `--`. A pure color policy resolves CLI mode, terminal state, `NO_COLOR`, and output format; the human renderer receives the resulting boolean and owns adaptive units and ANSI styling. JSON models and serialization remain unchanged.

**Tech Stack:** Rust 1.85+, Clap 4, standard-library terminal detection, Node.js npm launcher tests, GitHub Actions, npm trusted publishing, crates.io.

## Global Constraints

- Continue supporting x86-64 Windows and Linux only.
- Preserve explicit `--` syntax for backward compatibility.
- Require every BenchGuard option to appear before a delimiter-free target.
- Preserve `benchguard.json` schema version `1` and integer nanoseconds/bytes in JSON.
- Never emit ANSI escapes in JSON.
- Keep exit codes `0`, `1`, and `2` unchanged.
- Publish npm without a long-lived npm token.

    for record in [
        ["benchguard", "record", "build", "npm", "run", "build", "--silent"].as_slice(),
        ["benchguard", "record", "build", "--", "npm", "run", "build", "--silent"].as_slice(),
